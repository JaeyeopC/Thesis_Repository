# Exploring Pedagogical Alignment of LLMs Using Student Errors and Tutor Moves

Code and data repository for the Master's thesis
**Exploring Pedagogical Alignment of LLMs Using Student Errors and Tutor Moves**
Jaeyeop Chung, M.Sc. Data Engineering and Analytics, Technical University of Munich (2026).

## Overview

The thesis investigates whether preference optimization can align an LLM tutor with the tutor moves that human tutors use in response to specific student error types. The pipeline consists of three stages, each kept in its own folder:

1. **Classifier** – *Annotation transfer:* StepVerify dialogues are matched to their MathDial counterparts and the MathDial tutor-move labels (Focus, Probing, Telling, Generic) are transferred, yielding the aligned dataset that pairs student error types with tutor moves; the MathDial dialogues not used in this step are held out as SFT data. *Classifier training:* tutor-move classifiers are compared over 18 configurations – two encoders (RoBERTa-base, and a domain-adapted variant further pre-trained on QATD2k and MathMentorDB) × three input representations (tutor-turn only, preceding-1, all turns) × three objectives (weighted cross-entropy, focal loss, AUC maximization) – and the best-performing classifier is used to estimate tutor-move posteriors in the following stages.
2. **Preference Dataset** – Candidate tutor responses are generated by several LLMs and scored by combining the classifier posteriors with PPMI-based student error–tutor move utilities; the score margins define the preference pairs.
3. **SFT / DPO / Evaluation** – Llama-3-8B-Instruct is fine-tuned with SFT (LoRA) and then with DPO on the top 10 / 30 / 50 % of preference pairs. Base, SFT and DPO models are evaluated with gpt-4.1-mini as an LLM-as-a-Judge (Desired Annotation Match Rate, DAMR).

## Repository Structure

| Folder | Stage | Main notebooks |
|---|---|---|
| `0__final_classification/` | Classifier | `final_00_01` (annotation transfer), `final_00_03` (input representations), `final_00_04b` (aligned-dataset statistics), `final_00_05` (SFT data from unused MathDial rows), `final_99_00`–`final_99_04` (domain corpus preparation and domain-adaptive pre-training), `Final_01`–`Final_06` (classifier training; `01–03` RoBERTa-base / `04–06` domain-adapted encoder, with `Weighted_CE` / `DAM` (AUC maximization) / `Focal` objectives and `all_turns` / `preceding_1` / `tutor_turn_only` inputs) |
| `1__tutor_response_generation__preference_dataset_construction/` | Preference Dataset | `Final__stepverify_train_test_split`, `Final__Calculate__PMI_table__train_only`, `Fianl__Preference_Data_Construction__*`, `Final__Preference_data_Statstic_Summary__train_only` |
| `2__SFT_DPO__/` | SFT / DPO / Evaluation | `Final__SFT_SFT_SFT`, `Final__DPO_DPO_DPO__01/03/05`, `Final__SFT_DPO_Inference_generation`, `Final__SFT_DPO_Pedagogy_Evaluation`, `Final__SFT_DPO_Pedagogy_Evaluation_Anlysis` |
| `figure_notebooks/` | Figures | `result_5_1`, `result_5_2`, `result_5_3` – produce the figures and tables of Chapter 5 from the saved outputs of the three stages (no training or generation) |

Each folder also contains the data used at that stage (`data/`, `train_test_split/`, `data_pmi_table/`, `data_preference_train_only/`, `sft_data/`, `pedagogy_evaluation/`). Trained model weights and LoRA adapters are not included. Large data files are tracked with Git LFS (`git lfs install && git lfs pull` after cloning).

## Environment

### Runtime

- All training notebooks (classifier, SFT, DPO, inference) were run on **Google Colab** GPU runtimes (NVIDIA A100 80 GB / NVIDIA RTX PRO 6000 Blackwell), Python 3.13.
- The analysis and evaluation notebooks (dataset statistics, LLM-as-a-Judge evaluation and its analysis) run on CPU.
- The Colab notebooks mount Google Drive and change into `/content/drive/My Drive/Colab_Notebooks`; place the stage folders there or adjust the path in the setup cell.

### Installation

```bash
pip install -r requirements.txt
```

`requirements.txt` lists all packages with the versions used in the experiments. The SFT / DPO notebooks additionally run the following in their first cell, which is what produced these versions on Colab:

```bash
pip install --upgrade --no-cache-dir transformers trl datasets peft accelerate bitsandbytes safetensors
pip install --upgrade "torchao>0.16.0"
```
